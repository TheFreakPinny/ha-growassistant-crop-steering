# Native diagnostics (Phase 3C)

Normal Home Assistant setup now adds **12 read-only diagnostic entities** to the
existing GrowAssistant device. The legacy Blueprint remains the production
executor. Native irrigation stays disabled; diagnostics expose no activation
switch, button, service, action, acknowledgment or override. They do not create
PumpController, ShotCoordinator, Scheduler or CycleController, repair recovery,
change VWC averaging, or write native journals.

## Entity reference

All new entities have HA category `diagnostic`, stable unique ID
`<config_entry_id>_<key>`, and no polling per entity. Entity IDs are generated by
HA from the device name and translated entity name and can be renamed by users.
Existing entity IDs, unique IDs and configuration keys are preserved.

| Key | Platform | State and useful attributes |
| --- | --- | --- |
| `native_engine_status` | sensor | `disabled`; production policy, execution state `not_evaluated`, Blueprint executor policy |
| `native_activation_available` | binary_sensor | Always `off`; machine blocking reasons and human explanations |
| `native_sensor_readiness` | binary_sensor | `on` only when Phase 3B's provisional VWC policy passes; average, counts, rejection map, freshness policy, reasons and explanations |
| `native_vwc_configured_count` | sensor | Count of distinct configured VWC entities |
| `native_vwc_valid_count` | sensor | Count of fresh, valid, non-restored readings |
| `native_vwc_rejected_count` | sensor | All rejected readings; `stale_count`, `unavailable_count`, and per-entity rejection map |
| `native_vwc_quorum` | binary_sensor | `on` when both minimum count and percentage pass; policy and assessment attributes |
| `native_vwc_disagreement` | binary_sensor | `on` above allowed spread; `off` within spread; `unknown` with fewer than two valid readings |
| `native_recovery_classification` | sensor | `not_evaluated`, `historical_evidence_present` or `historical_review_required`; historical reasons, Store statuses and snapshot time |
| `native_pump_ownership` | sensor | Always `unverified`; configured target and observed HA pump state/time, physical off remains unverified |
| `native_migration_readiness` | sensor | Always `ineligible`; separate checklist attributes, blocking reasons and human explanations |
| `native_last_shot_outcome` | sensor | Persisted outcome of the uniquely latest timestamped operation, or `unknown`; operation ID, original state, timestamps, delivery and accounting evidence |

Binary `off` for activation means prohibited, not a fault that can be cleared.
Sensor readiness/quorum can be `on` while migration and activation stay ineligible.
Quorum alone can pass while disagreement blocks sensor readiness. Rejected count
includes invalid, restored and timestamp-invalid peers, beyond stale/unavailable.
No state is interpreted as permission to operate a pump.

## Evidence sources and limits

- **Live observation:** Sensor readings and HA timestamps are assessed using the
  unchanged Phase 3B `assess_sensors` logic. Defaults: maximum age **300 seconds**,
  at least **one** valid sensor, **100%** of distinct configured sensors valid,
  maximum spread **10 VWC percentage points**. These provisional diagnostics are
  not new integration options and do not change Blueprint arithmetic averaging.
  `last_updated` is HA receipt time, not physical acquisition time. Unchanged
  repeated reports do not reset it. Restored values are rejected. A single sensor
  cannot establish agreement with peers, so disagreement is unknown.
- **Persisted snapshot:** The three existing native Store files are read once per
  entry setup/reload. Attributes include `loaded_at` and `stores`, with statuses
  `missing`, `loaded`, `no_pending_record` (cleared pump recovery), `invalid`,
  `unsupported_or_invalid_envelope` or `load_failed`. Raw JSON is read in HA's
  executor, bypassing Store loading because Store can migrate records or rename
  corrupt files even when configured read-only. Diagnostics never save, remove,
  rename or migrate journals. Pending in-memory writes and private harness
  execution are not live production evidence. Reload to obtain a new snapshot.
- **Not evaluated / unverified:** No native runtime is initialized to obtain
  diagnostics. Missing history cannot prove clean restart, idle, reconciled state,
  Blueprint relinquishment, exclusive ownership or physical pump-off. Current
  recovery readiness and cycle reconciliation stay `not_evaluated`; ownership,
  Blueprint relinquishment and physical off stay `unverified`. Observed HA `off`
  cannot prove physical shutdown or the absence of other pump writers.

Recovery classification concerns **historical evidence**, not a running native
controller. Older interrupted/fault records require review even without an explicit
recovery flag. Uncommitted/missing accounting, nonterminal operations, possible
delivery, retained pump records and cycle/checkpoint discrepancies are surfaced
on an assessment copy; originals remain unchanged. Healthy sensors cannot erase
historical reasons. Historical records without identified problems still cannot
establish current recovery readiness or restore ownership.

Last-shot outcome never uses the existing Blueprint last-shot options/counters.
Missing outcomes, missing/invalid/naive reservation timestamps or ties yield
`unknown`. A newer operation with no recorded outcome is not replaced by an older
completed shot. `completed` means the journal recorded software completion, not
measured delivered volume, physical pump-off or current activation eligibility.
The original state/accounting attributes may still identify a recovery problem.

## Migration checklist

`native_migration_readiness` reuses Phase 3B's `migration_eligibility()` and exposes:

| Attribute | Meaning in normal operation |
| --- | --- |
| `sensor_readiness` | `ready` / `blocked` from the live provisional VWC assessment |
| `recovery_readiness` | `not_evaluated`; historical review is reported separately |
| `pump_off_verification` | `unverified`; HA off is only an observation |
| `blueprint_relinquishment` | `unverified`; diagnostics never disable/discover/acknowledge automations |
| `exclusive_pump_ownership` | `unverified`; no ownership mechanism exists |
| `cycle_state_reconciliation` | `not_evaluated`; no reconciliation is performed |
| `overall_activation_eligibility` | Always `false` |
| `native_activation_allowed` | Always `false` |
| `review_eligible` | Always `false` with unevaluated recovery and unverified ownership/off/state |

Full future migration requirements remain in [native safety and migration](native-safety-migration.md).
Readiness display does not implement any checklist operation.

## Example dashboard

Use HA's entity picker to replace `tent_1` IDs with the actual IDs from your device.
This is an observation card, with no irrigation actions. More detailed rejection,
blocking-reason and historical-evidence attributes are available in More info and
Developer Tools → States. Additional dashboards can read those attributes directly.

```yaml
type: entities
title: Native diagnostics — read only
show_header_toggle: false
entities:
  - entity: sensor.tent_1_native_engine_status
  - entity: binary_sensor.tent_1_native_activation_available
  - entity: binary_sensor.tent_1_native_sensor_readiness
  - entity: sensor.tent_1_native_vwc_configured_count
  - entity: sensor.tent_1_native_vwc_valid_count
  - entity: sensor.tent_1_native_vwc_rejected_count
  - entity: binary_sensor.tent_1_native_vwc_quorum
  - entity: binary_sensor.tent_1_native_vwc_disagreement
  - entity: sensor.tent_1_native_recovery_classification
  - entity: sensor.tent_1_native_pump_ownership
  - entity: sensor.tent_1_native_migration_readiness
  - type: attribute
    entity: sensor.tent_1_native_migration_readiness
    attribute: blueprint_relinquishment
    name: Blueprint relinquishment
  - type: attribute
    entity: sensor.tent_1_native_migration_readiness
    attribute: cycle_state_reconciliation
    name: Cycle reconciliation
  - entity: sensor.tent_1_native_last_shot_outcome
```

## Lifecycle and validation

One shared coordinator handles relevant state events and entry-option updates;
sensor selectors are rebound when options change, including explicit clearing.
One **60-second timer** bounds the display delay when readings age without events.
There is no recurring journal polling. Reload refreshes history and preserves IDs;
successful unload removes the timer, state/options listeners and entity dispatcher
subscriptions. Failed platform unload retains diagnostics for retry; failed setup
cleans its resources. Unavailable devices do not stop Blueprint setup.

Design and architecture review: [native diagnostics design](native-diagnostics-design.md).
Tests use HA fixtures, synthetic helpers, execution-constructor guards and mocked
pump services; real corrupt-file preservation is tested locally. No production
Home Assistant instance or irrigation hardware is accessed.

Local validation passed **747 tests** (**53 new cases**) on Python **3.13.16**,
HA **2025.12.5** and fixture **0.13.301**, after the **694-test** PR #74 baseline
passed. Ruff lint/format, Python compilation and Git whitespace checks passed.
GitHub Actions results are recorded on the draft PR.
